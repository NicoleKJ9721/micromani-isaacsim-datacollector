# 配置完成后的错漏复核与补充建议

本复核在配置和13帧数据导出验收完成之后进行。以下内容与已通过的14项场景检查区分。

## 已定位并修正

- 非ASCII机器人名称导致导入根路径与脚本不一致：在构建副本规范名称，原URDF不改。
- 材质未覆盖实例化网格：展开实例并绑定实际视觉网格，补齐UV。
- 默认驱动无阻尼、位置命令未同步驱动目标：显式设置仿真增益并同步位置目标/速度状态，Z轴测试通过。
- 腕相机被结构遮挡：按运行时刚体位姿和USD轴约定设置局部外参，用实际渲染选择无遮挡视角。
- 本地腕力读取把DOF序号当joint序号：改为关节元数据索引，避免固定关节造成错行；设备上已有同类修正予以保留。
- 原录制没有独立夹持接触观测：增加四指接触传感器及双夹爪数据字段。
- 官网当前规格与旧记录不一致：记录24 V和≤0.2 kg，不把上限当精确质量。

## 正式训练或力控前应优先完成

1. **夹口几何标定。** 本次启动显式使用zero_gap_mm=0，它是虚拟零位约定，没有证明CAD两接触面的真实间距为0。应从接触面几何求实际gap(q)，核验左右方向、工作原点及夹爪行程；否则不能把输出直接当实机mm开口。
2. **夹持力语义。** 当前标量是双指总接触幅值均值，可能包含非夹持面的接触和冲击；只有双侧合适接触才支持夹持解释。建议随数据保存每指原值、双侧接触标志、接触对象与沿闭合方向的力，增加已知静载和卸载恢复测试。当前探针测试只证明能检测接触。
3. **时间与吞吐。** 实测短段约3.23帧/s；30为仿真时间采样率。应增加相机rendering_time、接触传感器time、world.current_time及墙钟单调时间的逐帧来源记录，不能仅靠按序号生成的时间戳或图像hash证明同步。优先比较关闭无用渲染窗口、轻量渲染、异步落盘与视频存储的实际收益，再决定硬件升级。
4. **旧控制入口。** `micromani_control_bridge.py::_packet_to_command` 仍没有统一拒绝非有限值和全部关节越限；这是原有入口的问题。新录制器验证了14维目标，但不能由此推断旧桥也已安全。旧桥再次对外使用前补齐同样检查和拒绝路径测试。
5. **录制可追溯性。** 新UDP录制入口和设备原有record_session入口并存，契约实现不同，禁止仅凭同为14维或相似版本名混用。应统一一个正式入口，并保存场景hash、光学外参、驱动增益、材质/灯光版本和完整控制来源。当前设备原有入口的场景hash逻辑应在整合时保留。
6. **全局视野。** 本次global用于整机概览，宽约946 mm，微操作目标的像素密度低于原150 mm工作区设想。正式采集建议将训练global设为任务工作区，并保留独立整机预览视角，不把整机展示画面直接当最佳训练视角。
7. **真实物理边界。** 接触力来自PhysX，位置直接设置会影响冲击与力响应。后续抓取/插入研究宜采用持续位置目标驱动，验证摩擦、质量、刚度、接触offset及求解步长，完成一次可解释的夹持-保持-释放任务；不能把本次接口验收当精密力控结果。

## 可以发散补充的方向

- 每个episode固化工件、接触材质、任务成功条件和操作者/控制来源；视野测试蓝块默认排除于正式任务数据。
- 增加无工件、单指接触、双指夹持、滑移、释放和腕力过载等对照场景，区分腕部受力与夹持载荷。
- 先做不少于三段两分钟连续采集，检查掉帧、显存峰值、力饱和和恢复；再接PICO真人连续遥操作。
- 在物理/光学校验完成后，再进行灯光、材质、纹理、相机位姿和工件位置的可追溯随机化，避免随机化掩盖基础配置错误。

这些是后续验证或开发项，本轮没有将其表述为已完成，也没有额外引入依赖或修改实机保护。
